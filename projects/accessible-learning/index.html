01 / The challenge

From knowing the rule
to making the choice.

A control can look right and still be difficult to use. A learner who is new to accessibility needs more than a list of guidelines: they need to connect a design choice to someone’s experience.

This personal project explores that connection through short scenarios, concrete code examples, and feedback that explains the reasoning behind an answer.

An independent portfolio prototype, informed by my experience developing courseware and production software. It does not reproduce client course content.

02 / Learning objectives

Three decisions worth practising.

01

Recognise the barrier

Identify why an interaction that works with a mouse may fail for someone using a keyboard.

02

Choose meaningful HTML

Select a native control that communicates its purpose and supports familiar interactions.

03

Make the next step clear

Choose useful labels and feedback that help learners understand what happens next.

04 / Behind the build

Small steps.
Purposeful interactions.

Start with a recognisable situation

Each question presents a practical interface decision. This gives learners a reason to engage before introducing the underlying principle.

Explain the answer, not just the score

Feedback connects the selected pattern to its effect on the user. Learners can change their answer and retry without a timer or penalty.

Make the learning interface accessible

The preview uses native radio buttons, grouped questions, visible keyboard focus, and a live region for feedback. Content reflows on small screens, and reduced-motion preferences are respected.

Keep the implementation easy to extend

HTML provides the document structure, CSS controls presentation, and JavaScript holds the question data and interaction logic. The page runs as a static site without a build step.

05 / What comes next

A foundation for the full experience.

The current showcase includes a three-question interaction prototype. The next stage is a guided lesson with interactive examples, a review screen, and learner progress. Learner testing and a broader accessibility review are planned before calling the module complete.
